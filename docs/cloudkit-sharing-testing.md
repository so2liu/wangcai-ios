# 旺财 · 家庭共享真机联调清单

> 适用范围：CKShare 家庭多人共享（PR #4）。
> 代码已通过 Xcode 编译，但 CloudKit 共享的运行时行为**必须真机 + 两个 iCloud 账号**才能验证。
> 本清单按「环境准备 → 单人同步 → 多人共享 → 冲突与边界」顺序走。

## 一、前置环境

- **两台真机**（模拟器无法可靠测试 CKShare / 推送），分别登录**两个不同的 iCloud 账号**。
  - 设备 A = 发起人，设备 B = 受邀者。
- 两台设备都在「系统设置 → iCloud」处于已登录、网络可用状态。
- Apple 开发者后台：
  - 确认 App ID 勾选 iCloud（CloudKit）与 Push Notifications。
  - 确认 CloudKit 容器 `iCloud.com.yueyu.WorthSnap` 存在。
  - Provisioning Profile 包含上述能力。
- CloudKit Dashboard：
  - 首次写入后会自动生成记录类型（`Ledger` / `Member` / `Account` / `Snapshot` / `SnapshotEntry` / `AccountType` / `Tag`），每类含 `payload`(Bytes，加密) + `updatedAt`(Date/Timestamp) 字段。如未自动建出，手动按此 schema 建。
- 上线前：把 `WorthSnap.entitlements` 的 `aps-environment` 从 `development` 改为 `production`（或交由 Xcode 按构建配置注入）。

## 二、单人同步（先确认基础链路）

仅用设备 A：

1. 全新安装，进入设置 → 家庭共享，打开「iCloud 同步」。
   - 预期：状态从「同步中…」变为「已同步」；若未登录 iCloud，应提示「请先在系统设置登录 iCloud」。
2. 新增一个账户、填一笔金额。
   - 预期：CloudKit Dashboard 的 private database `Family` zone 里出现对应记录。
3. 归档该账户。
   - 预期：Dashboard 中对应记录更新为归档状态；历史快照仍保留。

## 三、多人共享（核心流程）

1. **发起邀请（设备 A）**：设置 → 家庭共享 → 「邀请家人加入」。
   - 预期：弹出系统共享界面（`UICloudSharingController`），可选 AirDrop / 信息 / 复制链接 / 二维码。
   - 选一种方式把邀请发给设备 B。
2. **接受邀请（设备 B）**：在设备 B 打开邀请链接。
   - 预期：系统拉起旺财，`userDidAcceptCloudKitShareWith` 被触发，App 切换为「受邀者」角色，开始拉取家庭数据。
   - 预期：设备 B 的账本被 A 的家庭账本**取代**（adopt 共享数据），账户、快照、成员全部出现。
3. **认领身份（设备 B）**：设置 → 家庭成员，确认成员列表含 A、B 两人；把属于自己的账户归属改到本人。
   - 预期：总览「按归属」三栏在 A 设备显示「我的=A 的、TA的=B 的」，在 B 设备自动镜像互换。
4. **双向编辑**：A 改自己账户金额、B 改自己账户金额。
   - 预期：几秒内（依赖推送/拉取）对方设备看到更新；两端家庭净资产一致 = 三栏之和。
5. **权限验证**：A 尝试编辑归属 B 的账户资料，B 尝试更新指定由 A 负责的月度余额。
   - 预期：两端均显示只读或指定更新人，不能越权保存；共同账户允许家庭成员维护。
6. **加入前保护**：设备 B 在加入前先建立个人账本，再接受邀请。
   - 预期：App 明确提示共享账本会替换当前账本；确认后生成 `worthsnap-before-family-join.json`，可从设置导出并成功恢复。

## 四、冲突与边界

1. **后写覆盖（LWW）**：让两台设备**离线**各改同一个账户金额，再先后联网。
   - 预期：以 `updatedAt` 较晚者为准，静默覆盖，不报错、不双写。
2. **成员离开**：在成员管理移除一名成员。
   - 预期：该成员被归档；其录入的账户与历史**保留**，其负责的账户转交给本人（人走数据留）。
3. **停止共享**：发起人在系统共享界面移除参与者或停止共享。
   - 预期：受邀者看到“家庭共享已不可用”，本地最后一次同步副本不被清空。
4. **关闭后重开**：受邀者关闭 iCloud 家庭同步，再重新开启。
   - 预期：仍以参与者身份连接原共享 zone，不会错误创建自己的新家庭。
5. **安全模式不受影响**：制造一次本地数据损坏，确认仍进入安全模式且**不触发**云端覆盖。

## 五、已知未决 / 观察点

- `currentMemberId` 为本设备视角、刻意不同步——确认两端「我的/TA的」各自正确，不串台。
- `AccountType` / `Tag` 无独立时间戳，合并采「远端覆盖」策略；自定义类型在双端并发改名属低频边界，留意是否符合预期。
- 推送时延：`CKSyncEngine` 自动同步依赖静默推送，弱网下可能有秒级~分钟级延迟，非 bug。
- 受邀者接受共享后，其**原有单机数据**会让位于共享家庭数据；若该用户此前已在单机录入，需产品上明确「加入家庭=采用对方账本」的取舍。
